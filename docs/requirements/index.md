# Requirements index

Requirements are identified as `REQ-<CATEGORY>-<NNN>` and must be traceable to architecture, tests, and roadmap phase.

## Categories

| Category | Scope |
|---|---|
| `REQ-STD` | Standards baseline and profile conformance. |
| `REQ-SCOPE` | Scope boundaries and non-goals. |
| `REQ-SCHEMA` | Supported schema constructs. |
| `REQ-BIND` | XSD-to-Java binding rules. |
| `REQ-GEN` | Code generation behavior and deterministic output. |
| `REQ-MODEL` | Generated model type style and invariants. |
| `REQ-XML-W` | XML writer/marshaller behavior. |
| `REQ-XML-R` | XML reader/unmarshaller behavior. |
| `REQ-VAL` | Validation behavior and diagnostics. |
| `REQ-NS` | Namespace, QName, prefix, and package mapping. |
| `REQ-RES` | Schema include/import resolution and offline policy. |
| `REQ-RT` | Runtime library constraints. |
| `REQ-NI` | GraalVM Native Image behavior. |
| `REQ-PERF` | Performance, memory, and streaming targets. |
| `REQ-SEC` | XML security and resource safety. |
| `REQ-BUILD` | Build, Gradle, dependency, CI, offline behavior. |
| `REQ-QA` | Static analysis, formatting, coverage, architecture tests. |
| `REQ-DOC` | Documentation and examples. |
| `REQ-AGENT` | Coding-agent governance. |
| `REQ-REL` | Release, versioning, and artifact publishing. |

See `taxonomy.md`, `phase-1-requirements.md`, and `traceability-matrix.md`.
